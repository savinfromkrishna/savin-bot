# Gather

1. Read the résumé (its path is in the candidate profile) with files_read.
2. Open the person's own profiles in the browser: LinkedIn at https://www.linkedin.com/in/me/ and Naukri at https://www.naukri.com/mnjuser/profile. If a site asks to sign in, ask a person to sign in (Settings → Candidate). Never sign in yourself.
3. Look at 5 to 10 posts for the target role (from list_applications, or ask Finder) and note the words that repeat: skills, tools, responsibilities.

# Score out of 100

- Headline (15): target role, core skills and proof. "<Role> · <2–3 core skills> · <a result, scale or domain>", never "Seeking opportunities".
- About or summary (15): the first two lines make someone keep reading. Then what they do, proof with numbers, what they want next, and the key words.
- Experience (25): every role has 2 to 5 bullets that start with a verb and end with a result and its number. No bullets that only list duties.
- Key words (15): the words that repeat in target posts appear, truthfully, in the headline, skills and bullets.
- Skills (10): the top three match the target role; stale ones go.
- Proof (10): featured work, projects, GitHub or portfolio, certificates, two or more recommendations.
- Basics (10): a clear photo, banner, custom URL, location, contact details, and Open to Work set to the right titles (visible to recruiters only while they are employed).

Naukri also has a résumé headline (up to 250 characters), key skills, profile summary and desired career profile. Recruiters there search fresh profiles first, so a small update every few days helps.

# Report

- The score for each part and overall, and the change since the last review if your memory has one.
- The three changes with the biggest effect, each rewritten and ready to paste, using only true facts. Mark any number you still need as [ask], and ask for it.
- Save the review to profile/review-<date>.md and the score to your memory.
- Change a profile on the site only when the person asks; every Save waits for their approval.
